# 카메라(ESP32-CAM) 신호등 — ESP32 펌웨어 + 아두이노 버전 D

> 이 브랜치(`extra/esp32cam`)의 추가 프로젝트. 작업 보고 : [`REPORT_20261111.md`](REPORT_20261111.md) · 다음에 할 일 : `main` 의 [`NEXT.md`](https://github.com/CHOESEUNGJUN/4wd_car_project/blob/main/docs/NEXT.md)

**원칙 : 카메라로 라인 주행은 하지 않는다.** 라인은 차(아두이노)가 **라인센서 3개 + PID** 로 따라가고,
카메라는 **신호등과 정지 표지판만** 보고 차에 신호 글자를 보낸다 (빨강 = 정지, 노랑 = 서행, 초록 = 보통, 정지 표지판 = 3초 정지 후 출발).

교안 4팀은 PC 파이썬(OpenCV)이 영상을 받아 판단하고 PC 블루투스로 차에 `g`/`s` 를 보낸다.
우리는 **ESP32 안에서 바로** 보고 판단해서 블루투스로 보낸다 (PC 없음, 영상 전송·PC 처리 지연 없음). 웹 화면은 보기·조종용.

> 2026-11-11 ~ 16 에는 카메라 라인 인식(마스크·모폴로지·라인 추적)과 카메라 주행(`G L R Q W`)도 있었지만 원칙이 바뀌어 뺐다
> (커밋 `6fe7773` 까지의 코드에 남아 있음).

## 0. ESP32-CAM 다루기 (매번 이 순서)

처음 한 번은 4장(올리기)과 5장(와이파이)을 먼저. 그다음부터는 이것만.

1. **핫스팟 켜기** : 아이폰 개인용 핫스팟 (**호환성 최대화** 켬). 노트북·폰도 이 핫스팟에 연결.
2. **차 켜기** : 아두이노(버전 D) 전원 → HC-06 빨간 LED 깜빡 (아직 아무도 안 붙음).
3. **ESP32-CAM 켜기** : 5V 외부 전원. 앞 흰 LED 가 깜빡이다가 핫스팟에 붙으면 **계속 켜짐** (뒤 빨간 LED 도 켜짐).
4. **웹 열기** : 브라우저로 **http://gulno-cam.local** → 위 배지 "카메라" 가 초록이면 연결.
5. **차 블루투스 연결** : 블루투스 칸 **연결** (처음이면 **기기 찾기** → 목록에서 차 HC-06, PIN 1234). 켤 때마다 한 번 눌러야 함 (자동으로 붙지 않음). 붙으면 배지 "차 블루투스" 초록, 차 상태 칸에 숫자가 나옴.
6. **신호등 인식 : 켬** → 아이폰 굴노 앱 **신호등 화면** 을 카메라 앞에. 영상 테두리가 지금 신호 색으로 바뀜.
7. **라인센서 주행** : 차를 선 위에 두고 누름 (0.5초 서 있다가 출발). 멈출 때 **정지 · 수동** (또는 스페이스, ■).
8. **끝낼 때** : 정지 · 수동 → 블루투스 **끊기** (폰 앱으로 차를 쓰려면 꼭) → 전원 끄기. 웹 화면만 닫아도 차는 5초 안에 멈춘다 (연결 신호 `h` 가 끊겨서).

### LED 보는 법

| LED | 상태 | 뜻 |
|---|---|---|
| 앞 흰색 (플래시) | 깜빡 (0.4초) | 연결 중 : 설정 모드, 핫스팟 붙는 중, 블루투스 붙는 중 |
| | 계속 켜짐 (약하게) | 다 연결됨. 폰 화면에 비쳐 색이 날아가면 `FLASH_DUTY` 를 낮춤 |
| 뒤 작은 빨강 | 천천히 깜빡 (0.5초) | **설정 모드** (설정용 와이파이 `GULNO-CAM-SETUP-xxxx` 켜짐) |
| | 계속 켜짐 | 핫스팟에 붙음 |
| | 빠르게 깜빡 | 핫스팟에 붙었다가 끊김 (핫스팟 확인) |
| | 꺼짐 | 전원 없음, 또는 시작 중 |

### 시리얼 모니터로 보기 (USB, 9600)

ESP32-CAM-MB 에 꽂고 `~/.pio-venv/bin/pio device monitor` (또는 Arduino IDE 시리얼 모니터 9600). 10초마다 안내 줄이 나온다.
맥에서는 시리얼을 여는 순간 ESP 가 다시 시작될 수 있다.

| 줄 | 뜻 |
|---|---|
| `I,ip,<주소>,gulno-cam.local` | 핫스팟에 붙음. 주소로도 열 수 있음 |
| `I,setup,<설정용 와이파이>,<암호>` | 설정 모드. 이 와이파이에 폰으로 붙어 핫스팟을 넣기 (5장) |
| `I,fail,<핫스팟>,<이유>` | 저장된 핫스팟에 못 붙은 이유 (못 찾음 / 5GHz / 암호 틀림) |
| `I,joined,<핫스팟>` | 설정 모드 중에 핫스팟이 나타나서 붙음 → 다시 시작 |
| `I,heap,<남은 내부>,<가장 큰 덩어리>,psram,<전체>,<남은>` | 메모리. 30분 동안 계속 줄면 누수 |
| `I,time,grab_ms,<a>,proc_ms,<b>,loop_ms,<c>` | 사진 받기 / 처리 / 한 바퀴 평균 시간 (ms). 한 바퀴가 곧 신호 반응 속도 |
| `I,step_us,sig,..,copy,..,jpeg,..` | 단계별 평균 시간 (µs). jpeg 는 영상을 볼 때만 |
| `I,sd,1` / `I,sd,0` | 켤 때 SD 카드가 있음 / 없음 (없으면 웹의 SD 기록 버튼이 꺼짐) |
| `I,restart,low_heap` | 메모리가 모자라 스스로 다시 시작함 |
| `E,camera` | 카메라를 못 찾음 → 리본 케이블 다시 꽂기. 업로드 직후 가끔 나오면 전원(USB)을 뺐다 꽂기 |

## 1. 구조

```
 5V 외부 전원 ──▶ ESP32-CAM (OV3660 컬러 160x120, 초당 약 20장, 모든 칸을 봄)
                   ├ 신호등 색 (빨강 / 초록 / 노랑) → 신호 글자
                   ├ 와이파이 (내 핫스팟) ──▶ 폰·노트북 브라우저 http://gulno-cam.local
                   │      컬러 영상(테두리 = 지금 신호), 색 픽셀 수, 차 상태, 주행 버튼, 조종, 블루투스, SD 기록
                   └ 블루투스 ──▶ HC-06 ──▶ 아두이노 (버전 D, 라인센서 3개 + PID 로 라인 주행)
                          보냄 : 조종 g b l r q w s a m h, 신호 x v n (0.2초마다)
                          받음 : 차 상태 줄 "ar,23,011,LINE,1,60" → 화면에 표시
```

- ESP32-CAM 은 **5V 외부 전원**으로 따로 켜고, 아두이노와는 **블루투스로만** 주고받는다 (선 없음).
- 웹 서버 하나(포트 80)가 화면·조종·영상을 다 한다. 영상은 2개 화면까지 동시에.

## 2. 신호등

| 신호 | 보내는 글자 | 차 (라인센서 주행, 자동 모드 그대로) |
|---|---|---|
| 🔴 빨강 | `x` | 장애물처럼 서서 기다림 (단계 `RED`) |
| 🟡 노랑 = 서행 | `v` | 기본 속도 `BASE` 120 → `SLOW_BASE` 100 으로 라인 추종 (코너 힘은 그대로) |
| 🟢 초록 / 신호 없음 | `n` | 보통 (빨강에서 바뀌면 그 자리에서 다시 라인 추종) |
| 🛑 정지 표지판 | `x` 3초 → `n` | **3초(`STOP_WAIT_MS`) 서 있다가 스스로 출발**. 출발한 뒤 5초(`STOP_IGNORE_MS`)는 같은 표지판을 무시 (지나가는 동안 또 서지 않게). 차 쪽은 그냥 `x`/`n` 이라 버전 D 그대로 |

- **라인은 차가 라인센서로 계속 보고, 신호만 카메라가 준다.** 모드(자동/수동)는 신호 때문에 바뀌지 않는다.
- **한 번이 아니라 계속 보냄** : ESP32 가 0.2초마다 (2초면 10번), 색이 바뀌면 바로 지금 신호 글자를 보내고, 차는 같은 글자가 오는 동안 그 상태를 유지. 몇 개 놓쳐도 그대로. 노랑은 `SIG_HOLD_MS`(1초) 넘게 안 오면 보통으로 본다. **빨강은 시간으로 안 풀린다** : 다른 신호 글자가 오거나 사람이 `a`/`m` 을 보낼 때까지 서 있음 (ESP32 가 꺼져도 안 달림). 신호등 인식을 끄면 ESP32 가 `n` 을 3번 보내 풀어 준다. 교안 4팀이 `g`/`s` 를 계속 보내는 것과 같은 생각.
- 사람 조종(소문자)은 신호와 상관없이 그대로. 버전 C 는 `x v n` 을 무시한다 (신호등은 버전 D 만).
- 빨강에서 멈춘 채 ESP32 가 꺼졌다면 : 폰 앱이나 웹으로 `m`(수동) 또는 `a`(자동)를 보내면 풀린다.

### 인식 방법

사진(`SIG_Y1` 줄 위쪽, 지금은 **화면 전체**)의 **모든 칸** 색을 **HSV**(교안 3팀 방식 : H 색상 0~359, S 채도, V 밝기)로 나눠 센다 : 빨강 H < 20 또는 ≥ 330, 노랑 35~75, 초록 85~170 (채도 ≥ 110, 밝기 ≥ 60), 흰색 = 채도 ≤ 50 이고 밝기 ≥ 170. 색상으로 보니 **어둡거나 밝거나, 빨리 달려 노출이 바뀌어도 같은 색**으로 잡힘. 켤 때 한 번 4096 색(R·G·B 각 4비트)의 종류를 표(`colorLut`, 내부 4KB)로 만들어 두고 칸마다 표만 봄 (계산 없음).
가장 많은 색이 `SIG_MIN`(160)개 넘게 **3장 연속**이면 그 신호 (**빨강은 2장** : 서는 쪽은 빨라야 안전). 신호 반응 ≈ 2~3장 × 약 50ms ≈ 0.1~0.15초 + 블루투스.

**빨간불과 정지 표지판 가르기** (둘 다 빨강) : 빨강 덩어리를 감싼 네모 칸에서 빨강이 차지하는 비율(**채움**)과 그 칸 안의 **흰색**(채도 낮고 밝음) 비율을 본다.
폰 빨간 화면(신호등)은 채움 86~100%·흰색 0%, 팔각형 표지판은 모서리가 비고 흰 테두리·글자가 있어 채움 61~68%·흰색 17~24% (2026-11-16 가짜 사진 시험).
네모 칸은 빨강이 3칸 넘게 있는 줄만 보고 위아래·좌우 끝에서 빨강의 3% 씩을 잘라 잡는다 (떨어진 빨강 점에 안 흔들리게). 흰색은 네모 **가운데 60%** 안에서만 센다 (표지판 글자는 가운데, 모서리 밖 흰 벽은 안 셈). 2026-11-18 실제 화면에서 빨간불을 표지판으로 본 것을 고침.
→ 채움 < `SIGN_FILL_MAX`(80%) 이고 흰색 ≥ `SIGN_WHITE_MIN`(4%) 이면 정지 표지판. 웹 화면에 채움·흰색 % 가 나오니 실제 화면으로 맞춘다.

- 웹 화면 영상 아래에 지금 센 **빨강 · 초록 · 노랑 픽셀 수**가 나온다 → 신호등을 보여 줬을 때 그 색이 `SIG_MIN` 을 넉넉히 넘는지, 신호등이 없을 때 바닥·물건 색이 걸리지 않는지 보고 맞춘다.
- 바닥·주변 물건 색이 걸리면 `SIG_Y1` 을 줄여 화면 위쪽만 보게 한다 (줄이면 영상에 그 경계가 흰 점선으로 나옴).
- 노랑이 하얗게 날아가거나 주변과 헷갈리면 파랑(가장 잘 구분됨)이나 주황(빨강과 가까움)으로 바꾸는 것을 검토.

### 신호등 (아이폰 앱)

아이폰 앱 굴노 아래쪽 **"신호등 화면"** 버튼 (차 연결 없이 됨). 화면 전체가 **초록 → 노랑 → 빨강** (순수 #00ff00 / #ffff00 / #ff0000).
누르면 다음 색, 아래 `자동 n초` 로 저절로 바뀌는 간격 (0 = 끔). 켜져 있는 동안 밝기 최대, 화면 안 꺼짐.
아래 **"정지 표지판"** 버튼 : 검은 바탕에 흰 테두리 + 빨간 팔각형(#ff0000) + 흰 STOP. 다시 누르면("신호등") 신호등으로.

## 3. 배선

| ESP32-CAM | 연결 |
|---|---|
| 5V | **따로 5V** (보조배터리 USB, 또는 5V 강압 모듈). 와이파이·블루투스·카메라·LED 가 순간 0.5A 넘게 먹어서 아두이노 5V 로는 부족. 모터 배터리와 같이 쓰면 출발할 때 전압이 떨어져 ESP 가 재시작할 수 있음 |
| GND | 5V 전원 GND |

아두이노와 선은 잇지 않는다 (블루투스로 통신). 업로드할 때는 ESP32-CAM-MB 받침 보드에 꽂는다.

## 4. 올리기

### ESP32-CAM (PlatformIO)

**Arduino IDE 로 올리면 안 된다** (예전 라이브러리로 빌드돼서 블루투스를 켜면 메모리 부족으로 멈춤).

1. 처음 한 번 : `python3 -m venv ~/.pio-venv && ~/.pio-venv/bin/pip install platformio`
2. ESP32-CAM 을 **ESP32-CAM-MB** 받침 보드에 꽂고 USB 연결.
3. 올리기 : `cd esp32/esp32cam_line && ~/.pio-venv/bin/pio run -t upload` (포트를 못 찾으면 `--upload-port /dev/cu.usbserial-xxxx`)
4. 시리얼 : `~/.pio-venv/bin/pio device monitor` (나가기 Ctrl+C)

- 처음 빌드는 ESP32 라이브러리를 `platformio.ini` 설정으로 다시 만드느라 약 2GB 를 받고 20~40분. 그다음부터는 1분 안팎.
- 처음 빌드가 `IncompatiblePlatform ... v6.2.0-post.1` 로 멈추면 같은 명령을 한 번 더 (pioarduino 버전 판단 문제).
- "Failed to connect" 면 MB 보드 IO0 버튼을 누른 채 RST → 떼고 다시.

### 차 (버전 D, Arduino IDE)

`arduino/team2_bt_cam/team2_bt_cam.ino` 를 열고 보드 Arduino UNO 로 업로드. 핀·PID 값은 버전 C 와 같다.

저주파 PWM : `arduino/motor_control_low_frequency_cam/` (버전 D 와 같고 모터 PWM 만 약 122Hz, 2026-11-16 시험 : 잘 돌고 더 부드러움). **먼저 배선 4개를 맞바꿈** (L298N ENA 선 5 → 9, IN2 선 9 → 5, ENB 선 6 → 10, IN3 선 10 → 6), 바퀴를 띄우고 방향부터 확인. 되돌릴 때는 선을 되돌리고 버전 D. 이유·비교 : `docs/PID.md` 끝

### 아이폰 앱 (Xcode)

`apps/ios_mac/MiniCar.xcodeproj` → Signing 에서 내 Apple ID 팀 → 아이폰 연결 → ▶ (`apps/README.md`). 처음엔 아이폰 설정에서 개발자 모드 켜기, 일반 → VPN 및 기기 관리 → 개발자 앱 신뢰.

## 5. 와이파이 연결 (프린터처럼)

핫스팟 이름·암호는 **코드에 적지 않는다** (공개 저장소). 처음 한 번 폰으로 넣어 주면 ESP32 안에 저장된다.

1. 연결할 와이파이를 켠다 — 폰 핫스팟이면 **2.4GHz** (아이폰 : 설정 → 개인용 핫스팟 → **호환성 최대화** 켜기).
2. ESP32-CAM 을 켠다. 저장된 핫스팟이 없거나 15초 안에 못 찾으면 **설정 모드** : 설정용 와이파이 `GULNO-CAM-SETUP-xxxx` 가 켜진다.
3. 설정용 와이파이 암호는 처음 켤 때 무작위 8글자로 만들어 저장한다. **USB 로 꽂고 시리얼 모니터(9600)** 를 열면
   `I,setup,GULNO-CAM-SETUP-xxxx,<암호>` 가 10초마다 나온다. 종이에 적어 두면 프린터 스티커처럼 계속 쓴다.
4. 폰에서 그 와이파이에 접속 → 설정 화면이 자동으로 뜬다 (안 뜨면 http://192.168.4.1).
5. 핫스팟 이름(목록에서 고름)과 암호를 넣고 **저장하고 연결** → 다시 켜지며 그 핫스팟에 붙고, 설정용 와이파이는 꺼진다.
6. 폰·노트북도 그 핫스팟으로 돌아가서 **http://gulno-cam.local** (안 되면 시리얼의 `I,ip,<주소>`).

### 어디서든 접속 (폰 종류 상관없이)

> **2026-11-18 부터 꺼 둠 (`DIRECT_AP` false)** : 자기 와이파이를 같이 켜면 내부 메모리 약 8KB 를 더 써서 블루투스를 켤 때 멈췄음. 지금은 프린터처럼 핫스팟을 잡으면 자기 와이파이를 끄고, 핫스팟을 못 찾을 때만 설정용으로 켬. 아래는 다시 켰을 때(`DIRECT_AP` true)의 설명.


| 방법 | 주소 | 되는 곳 |
|---|---|---|
| ① 이름 | `http://gulno-cam.local` | 아이폰·맥·PC (안드로이드 크롬은 못 찾을 때가 많음) |
| ② 핫스팟 주소 | 웹 화면 **"접속 주소"** 칸에 나옴 (예 `http://172.20.10.2`), 시리얼 `I,ip` | 같은 핫스팟의 모든 기기 |
| ③ **직접 연결** | ESP 자기 와이파이 **`GULNO-CAM-xxxx`** (설정용과 같은 이름·암호) 에 붙고 **`http://192.168.4.1`** | **모든 폰, 핫스팟 없이도.** 붙으면 화면이 로그인 창처럼 바로 뜨기도 함 |
| ④ 안드로이드 굴노 앱 **"카메라 화면"** | 같은 핫스팟에서 ESP 를 스스로 찾아 엶 (mDNS), 못 찾으면 ① → ③ | 안드로이드 |

- ③ 은 핫스팟에 붙은 뒤에도 ESP 가 자기 와이파이를 켜 둔 것 (`DIRECT_AP`, 핫스팟과 같은 채널). 암호는 웹 화면 "접속 주소" 칸과 시리얼 `I,setup` 에 나옴. 직접 연결한 폰은 인터넷이 안 됨 (ESP 만).
- 직접 연결은 와이파이를 하나 더 켜는 거라 내부 메모리를 조금 더 씀 → 블루투스까지 켠 상태에서 `I,heap` 확인 (2026-11-16 빌드만 함, 보드 확인 전).

- 다음부터는 켜면 바로 붙는다. 핫스팟을 바꾸려면 그 핫스팟을 끈 채로 켜면 설정 모드.
- 못 붙어 설정 모드가 돼도 저장된 핫스팟을 10초마다 다시 찾는다. 못 붙은 이유는 시리얼 `I,fail,<핫스팟>,<이유>` 와 설정 화면에.
- 아이폰 핫스팟은 맥에 IPv6 만 주기도 한다 (맥 주소가 `192.0.0.2`). ESP32 도 IPv6 를 켜 두었으니 맥에서는 **http://gulno-cam.local** 로 연다 (172.20.10.x 숫자 주소로는 안 열릴 수 있음).

## 6. 웹 화면 (http://gulno-cam.local)

노트북은 두 칸(왼쪽 영상, 오른쪽 조종·상태), 폰은 한 줄로 아래로 이어진다.

| 칸 | 내용 |
|---|---|
| 위 배지 | 카메라 연결 / 차 블루투스 연결 / 초당 장수 (fps) |
| 영상 | 컬러 영상. 신호등 인식을 켜면 **테두리 = 지금 신호 색** (빨강 / 초록 / 노랑, 정지 표지판 = 자홍, 없음 = 회색). 아래에 센 빨강·초록·노랑 픽셀 수, 빨강 덩어리 채움·흰색 % |
| 조종 | ▲ ▼ ◀ ▶ ↺ ↻ ■. 노트북은 방향키, Q·E 제자리, 스페이스 정지 (앱과 같은 규칙 : 누르는 동안 0.2초마다, 떼면 `s` 두 번) |
| 주행 | **라인센서 주행** (`a`) / **정지 · 수동** (`m`) / **신호등 인식 켬·끔** + 지금 신호 (정지 표지판이면 "n초 뒤 출발") |
| SD 기록 | **SD 기록 : 켬/끔** 버튼 + 지금 파일 번호와 저장한 장 수 (11장) |
| 차 상태 | 아두이노 상태 줄을 풀어서 : 모드, 동작, 앞 거리, 라인센서 ○●○, 단계, 오차 / 보정 |
| 블루투스 | **기기 찾기** (약 5초) → 목록(이름 · 주소 · 신호)에서 차를 누르면 연결 (PIN 1234). 고른 기기는 저장돼서 다음엔 **연결** 만. **끊기** 하면 폰 앱이 HC-06 을 쓸 수 있다 |
| 카메라 설정 | 좌우 반전 (이 보드는 기본 켬) / 위아래 뒤집기 / **회전 0° · 90° · 180° · 270°** (시계 방향) / **HSV 보기** (영상을 ESP 가 본 색 종류로 칠함 : 빨강·초록·노랑·흰색, 회색 = 신호 아님. 기준 맞출 때, 저장 안 함). 회전은 바로 적용·저장 |

- **주고받기는 웹소켓 하나** (`/ws`) : 조종 글자는 바로 (화면 → ESP32 → 블루투스 → 차), 신호·차 상태는 ESP32 가 0.2초마다 (신호가 바뀌면 바로) 밀어 준다. 화면이 열려 있는 동안 ESP32 가 차에 연결 신호 `h` 를 0.6초마다 대신 보낸다 (화면을 닫으면 끊겨서 자동 주행이 멈춤).
- 웹 영상은 핫스팟을 거쳐서 실제보다 늦게 보일 수 있지만 **차는 화면을 기다리지 않는다** (신호 글자는 ESP 가 바로 보냄).
- 안테나 하나를 와이파이·블루투스가 나눠 써서, 차와 연결되면 영상을 가볍게 보냄 (`JPEG_Q_BT`, `STREAM_MS_BT` 0.05초). 조종이 느려지면 `STREAM_MS_BT` 를 100~200 으로.
- **켤 때 기본 영상 = HSV (2026-11-18)** : JPEG 압축(한 장 55ms, 영상 작업·버퍼 약 9KB)이 없어 ESP 자원을 덜 씀. 웹 화면은 첫 상태 줄을 보고 HSV 영상 / 실제 영상 중 하나만 엶 (예전에는 JPEG 영상을 먼저 열었다가 끊음). 실제 컬러 영상은 웹 카메라 설정에서 HSV 보기를 끄면 됨
- **블루투스 연결 중 영상 (2026-11-18, 실측, 아직 해결 안 됨)** : HC-06 이 붙으면 ESP 와이파이 응답이 블루투스 끈 상태 0.2~0.3초 → **약 5초** 로 밀려 화면이 멈춤 (안테나 반반 나누기). 와이파이 우선(`esp_coex_preference_set(ESP_COEX_PREFER_WIFI)`)으로 바꾸니 좋을 때는 0.2~0.5초, 영상 HSV 3.5장 / JPEG 2.5장까지 돌아오지만, 가끔 9초 가까이 멈추는 구간이 아직 있음 (원인 미확인 : HC-06 이 끊겼다 다시 붙는 동안 블루투스가 안테나를 오래 잡는 것으로 의심). 참고 : 핫스팟 폰까지는 0.03초인데 ESP 까지는 블루투스를 꺼도 0.2~0.3초
- **블루투스를 켜면 멈추던 것 고침 (2026-11-18, 실측)** : 블루투스가 내부 메모리 약 60KB 를 써서 켜면 9~20KB 만 남았고, 화면이 끊기거나 안전장치가 재시작시켰음 (누수가 아니라 고정으로 쓰는 양이 늘어난 것 : 자기 와이파이 동시에 켜기 약 8KB + 새 기능 약 8KB). 고친 것 : (1) 자기 와이파이는 핫스팟을 잡으면 끔 (`DIRECT_AP` false, 프린터처럼) (2) 흰색·빨강 비트 표를 외부 메모리로, 보내기 작업 없앰 (3) 라이브러리 빌드에서 안 쓰는 블루투스 오디오(A2DP·HFP)·GATT 를 빼고 블루투스 작업 스택 8KB 두 개를 5KB·4.3KB 로. 결과 : 블루투스 끔 61~69KB → **약 80KB**, HC-06 연결됨 9~20KB → **33~36KB**, 연결 + 실제 영상(JPEG) 같이 → 약 24KB (재시작 없음). 연결 수를 1개로 줄이는 설정은 HC-06 을 찾기는 하는데 연결이 안 돼서 뺌
- **남은 문제** : 블루투스가 연결되면 안테나를 같이 써서 영상이 크게 느려짐 (같은 핫스팟에서 실측 : JPEG 초당 0.7장, HSV 영상 1.3장. 신호 판단은 그대로 초당 18~22장). 영상 화면이 2개 + 블루투스 찾기 중이면 메모리가 다시 11KB 까지 내려감
- **HSV 영상 (JPEG 없이, 2026-11-18)** : HSV 보기를 켜면 JPEG 영상을 끊고, 칸마다 색 종류를 "종류 3비트 + 이어진 칸 수 5비트" 로 묶어 웹소켓으로 보내 브라우저가 칠함. 신호를 세면서 같이 만들어 계산이 거의 없고 (JPEG 압축 55ms 없음) 한 장 약 1.4KB (JPEG 약 3.3KB). 같은 아이폰 핫스팟 연결에서 실측 : JPEG 초당 3~4장, **HSV 영상 5~11장**. 영상 장수를 막는 것은 ESP 가 아니라 **연결** : 핫스팟을 거치면 ESP 응답이 평균 0.12~0.27초 (핑 실측, 핫스팟 폰까지만은 0.05초) 라 초당 약 10KB 만 통과
- **웹소켓 보내기를 기다리지 않는 방식으로** : 상태 줄과 HSV 영상을 한 통로로 순서대로, 소켓이 못 받으면 건너뜀 (느린 화면 때문에 신호 판단이 멈추지 않게). 작은 조각 모으기(Nagle)를 꺼서 조종 글자·상태도 바로 나감
- **빨간불을 정지 표지판으로 잘못 본 것 고침 (실제 화면에서 발견)** : 빨강 덩어리 네모를 화면의 모든 빨강 칸으로 잡아서, 떨어진 빨강 점 몇 개가 네모를 키우고 그 안에 흰 벽이 들어갔음 (채움 32%, 흰색 11%). 이제 빨강이 3칸 넘는 줄만 보고 양 끝 3% 를 잘라 네모를 잡고, 흰색은 네모 **가운데 60%** 에서만 셈 → 같은 화면에서 채움 94~97%, 흰색 0% = 빨간불. 가짜 사진 27가지 통과 (`sh esp32/test/run.sh`)
- **웹 영상 빠르게 (2026-11-18)** : 영상이 끊겨 보이던 원인은 (1) 한 장 보낼 때마다 일부러 쉬던 시간 (0.1초, 블루투스 연결 중 0.2초 → 초당 약 8장 / 4장) (2) JPEG 압축 한 장 75~85ms (실측). 쉬는 시간을 0 / 0.05초로 줄이고, 압축 전에 사진을 한 번 더 복사하던 것(외부 메모리 38KB)을 영상 버퍼 2장을 번갈아 쓰는 방식으로 없앰 → 압축 **55~60ms** (실측), 영상 초당 약 15장 (블루투스 연결 중 약 9장, 계산값). 신호 판단은 그대로
- HC-06 은 한 번에 한 기기만 붙는다. ESP32 가 붙어 있으면 폰 굴노 앱은 블루투스로 못 붙는다 (신호등 화면은 블루투스 없이 됨).

## 7. 속도와 메모리

- **인지 속도 우선 (2026-11-16 결정)** : 카메라는 센서가 컬러를 가장 빨리 주는 **160x120** (초당 약 20장), 대신 신호는 **모든 칸**을 봐서 작은·먼 표지판도 잡음 (반지름 11px 정지 표지판 시험 통과 : 예전처럼 한 칸 건너 보면 기준 미달).
- 속도 (실측) : 한 바퀴 약 48ms (사진 받기 + 신호 세기 9~13ms, 영상을 볼 때만 영상용 복사 몇 ms). 신호 세기는 한 줄씩 내부 메모리로 옮겨서, 흰색은 비트로 적어 두고 셈 (외부 메모리를 다시 안 읽음). 신호를 세면서 같은 줄을 영상용으로도 복사 (사진을 외부 메모리에서 한 번만 읽음, 회전 중이면 따로). 사진마다 도는 함수(`detectSignal`, `shrinkView`)는 **IRAM + -O2** (ESP32 는 플래시 코드와 PSRAM 사진이 캐시를 같이 써서, 사진을 읽는 동안 코드가 캐시에서 밀려남) — 2026-11-16 빌드·결과 같음 시험만, 실제 시간은 다음에 `I,step_us` 로 확인
- **HSV 표 (2026-11-16)** : 가짜 사진 17가지에서 예전 RGB 기준은 12개(어두운 빨강·초록·노랑, 바랜 빨강, 어두운 표지판을 놓침), HSV 표는 17개 모두 맞음. 바닥(베이지·나무)·어두운 방·흰 벽은 신호로 안 봄.
- **카메라 칩은 OV3660 (2026-11-18 보드에서 확인, OV2640 이 아님).** 초당 장수는 센서가 정함 : 컬러 160x120 에서 드라이버가 센서 클럭을 40MHz 로 잡아 **45ms 마다 한 장 (초당 22.2장)** (VSYNC 핀으로 실측). 한 바퀴 48ms 중 처리는 약 7ms 뿐이고 나머지는 다음 사진을 기다리는 시간 → 코드를 더 줄여도 빨라지지 않음. 센서 클럭을 올려 보면 (PLL 배수 8 → 10) 센서는 초당 27.8장을 내지만 ESP32 가 못 받아 덜 찍힌 사진이 10초에 1장 → 28장으로 늘고, 배수 12 는 거의 다 깨짐 → 그대로 둠. 더 빠르게는 ESP32-S3 보드 (카메라 입력이 빠름)
- 시험해 보고 고른 것 : 320x240 은 4배 픽셀이지만 **센서가 컬러 320x240 을 초당 9~10장만 줘서** 한 바퀴 약 105ms (반응 2배 느림). 카메라 클럭 24MHz 는 빨라지지 않고 덜 찍힌 사진만 늘어남 (20MHz 유지).
- 화각 : 160x120·320x240 같은 4:3 작은 크기는 카메라 칩(OV3660, 2048x1536)이 **센서 전체를 줄여서** 만들어 이미 최대 화각. 더 넓게 보려면 **광각 렌즈(120° / 160°) 모듈 (OV3660 용, 또는 OV2640 광각 모듈)** 로 바꿔야 함 (지금 기본 렌즈 약 65~70°).
- 시험해 보고 뺀 방법 : 센서 JPEG(하드웨어 압축)로 받아서 다시 풀기 → 영상은 좋지만 ROM 디코더로 푸는 데 95ms 가 걸려 한 바퀴 110ms 로 더 느림.
- 시리얼에 가끔 `cam_hal: FB-SIZE: 149760 != 153600` 은 덜 찍힌 사진 한 장을 버린 것 (정상).
- 컬러 영상 JPEG 압축은 코어 0 에서, **새 사진일 때만**, 영상을 보거나 SD 기록 중일 때만 (신호 처리를 안 막음). 와이파이 절전 끔 (`WiFi.setSleep(false)`).
- Arduino IDE 용 ESP32 라이브러리로는 블루투스 클래식 + 와이파이 + 카메라를 같이 켤 내부 메모리(약 320KB)가 없다. 그래서 **PlatformIO 로 라이브러리를 다시 빌드**해서 블루투스·와이파이 메모리를 외부 메모리(PSRAM 4MB)에 먼저 두고, BLE 는 끈다 (`platformio.ini`).
- 사진·영상 버퍼는 PSRAM. 상태·명령은 고정 크기 버퍼 (메모리를 잡았다 놓았다 하지 않음). 블루투스는 "기기 찾기"·"연결"을 누를 때 켬. SD 는 기록할 때만 붙임. 여러 작업이 같이 쓰는 것은 잠금(mutex)으로.
- 안전장치 : 남은 내부 메모리가 `HEAP_MIN`(12KB)보다 적은 상태가 5초 이어지면 스스로 재시작 (핫스팟·블루투스는 저장돼 있어 다시 붙음).
- 카메라 칩(OV3660) 안의 ISP 는 하드웨어라 ESP 를 느리게 하지 않지만, 자동 노출·자동 화이트밸런스가 색이 바뀔 때 다시 맞추느라 잠깐 색이 틀어질 수 있음 → 신호가 늦으면 고정하는 것을 검토.

## 8. 카메라 달기와 맞추기

카메라는 라인을 안 보니 **앞을 본다** (바닥을 내려다볼 필요 없음).

- 차 앞쪽 가운데, 바닥에서 10~15cm, **앞을 보거나 아주 조금만 숙이게**. 신호등(폰)이 차 앞 30~60cm 에 있을 때 화면 안에 들어오게.
- 초음파 센서 앞을 가리지 않기. 서보 위에는 달지 않기 (시작할 때 돌아감). 양면 폼테이프 + 케이블타이로 단단히 (진동). 카메라 리본 케이블은 꺾이지 않게 여유.
- 거꾸로 달았으면 웹 화면 카메라 설정의 좌우 반전 / 위아래 뒤집기로, **옆으로(90도) 달았으면 회전**으로. 회전은 카메라 칩이 못 해서 영상(웹·SD)만 소프트웨어로 돌림 (90°·270° 면 120x160 세로 영상). 신호 판단(색 픽셀 수, 채움·흰색 %)은 돌려도 결과가 같아서 그대로.

1. 같은 핫스팟의 브라우저에서 **http://gulno-cam.local**, **신호등 인식 : 켬**.
2. 신호등을 안 보여 줄 때 센 픽셀 수가 모두 `SIG_MIN`(160)보다 한참 작은지 (주변 물건 색이 걸리면 `SIG_Y1` 을 줄이거나 카메라 방향을 바꿈).
3. 폰 신호등 화면을 실제 쓸 거리에 두고 세 색이 각각 넉넉히(수백 개) 잡히는지, 테두리 색이 바로 바뀌는지.
4. 차에 **버전 D** 를 올리고 라인센서 주행 + 신호등 : 빨강에 서고, 초록에 다시 가고, 노랑에 느려지는지. 서행에서 출발을 못 하면 `SLOW_BASE` 를 올림.
5. 이상하면 **SD 기록** 으로 찍어서 `esp32/rec_viewer.html` 로 봄 (10장).

| 이름 (어디) | 처음 값 | 뜻 |
|---|---|---|
| `SIG_Y1` (ESP) | `H` (화면 전체) | 이 줄 위쪽만 신호등으로 봄 |
| `SIG_MIN` (ESP) | 160 | 신호로 볼 최소 픽셀 수 (160x120 모든 칸 19200개 중 0.8%) |
| `CAM_SIZE`, `CW` / `CH`, `SIG_STEP` (ESP) | QQVGA, 160 / 120, 1 | 카메라·판단 크기와 몇 칸마다 볼지. 320x240 (`FRAMESIZE_QVGA`, 320 / 240) 은 더 멀리 보지만 반응 2배 느림 |
| `CAM_XCLK` (ESP) | 20000000 | 카메라 클럭. 24MHz 는 덜 찍힌 사진만 늘어남 |
| `SIGN_FILL_MAX` / `SIGN_WHITE_MIN` (ESP) | 80 / 4 (%) | 빨강이 네모 칸을 이보다 덜 채우고 흰색이 이보다 많으면 정지 표지판 |
| `STOP_WAIT_MS` / `STOP_IGNORE_MS` (ESP) | 3000 / 5000 | 정지 표지판에서 서 있는 시간 / 출발 뒤 같은 표지판 무시 시간 |
| HSV 기준 (ESP `RED_H1`…`WHITE_V_MIN`) | 빨강 H<20·≥330, 노랑 35~75, 초록 85~170, S≥110, V≥60, 흰색 S≤50·V≥170 | 실제 화면으로 재서 맞춤 (바닥이 주황·갈색이면 `RED_H1` 을 15 로) |
| `FLASH_DUTY` (ESP) | 30 | 앞 LED 밝기 (0~255). 폰 화면에 비치거나 뜨거우면 낮춤 |
| `SLOW_BASE` (버전 D) | 100 | 서행 기본 속도 (`MIN_PWM` 90 보다 커야 출발) |
| `SIG_HOLD_MS` (버전 D) | 1000 | 노랑이 이만큼 안 오면 보통으로 (빨강은 안 풀림) |

버전 D 의 나머지 바퀴 힘은 버전 C 자동 주행 값(`BASE` 120, `KP` 51, `CORNER_OUT` 180 / `CORNER_IN` −90) 그대로. PID 기초는 [`PID.md`](PID.md).

## 9. 문제 해결

| 증상 | 확인 |
|---|---|
| `gulno-cam.local` 이 안 열림 | **안드로이드면** 굴노 앱 "카메라 화면" 이나 직접 연결(와이파이 `GULNO-CAM-xxxx` → `http://192.168.4.1`) (5장 "어디서든 접속"). 폰·노트북이 **같은 핫스팟**인지. 뒤 빨간 LED 가 계속 켜졌는지. 시리얼 `I,ip,<주소>` 의 주소로 열기 (맥은 IPv6 때문에 이름으로 여는 게 나음). 안드로이드 일부는 `.local` 을 못 찾음 → 주소로 |
| 계속 설정 모드 (빨간 LED 천천히 깜빡) | 핫스팟이 켜져 있는지, **2.4GHz**(호환성 최대화)인지, 이름·암호가 맞는지. 시리얼 `I,fail` 이유 확인. 설정용 와이파이로 다시 넣기 (5장) |
| 핫스팟을 바꾸고 싶음 | 지금 핫스팟을 끈 채 ESP 를 켜면 15초 뒤 설정 모드 → 새 핫스팟 넣기 |
| 블루투스 **기기 찾기** 에 차가 없음 | 차 전원, HC-06 LED 깜빡(다른 기기에 안 붙음)인지. 폰 앱이 붙어 있으면 앱에서 끊기. 다시 찾기 |
| 블루투스가 붙었다 끊겼다 | ESP 와 차 거리, 전원 (5V 외부). 화면 "끊기" 후 "연결" |
| 주행 중 ESP 가 다시 켜짐 | 거의 **전원** : 5V 를 모터 배터리와 따로. 앞 LED `FLASH_DUTY` 를 낮추면 전류가 줄어듦. 시리얼에 `I,restart,low_heap` 이면 메모리 |
| 영상이 느림 | 핫스팟·JPEG 때문 (차의 신호 반응과는 상관없음). 화면을 2개 넘게 열지 않기 |
| 신호가 안 잡힘 | 웹의 픽셀 수 확인 : 그 색이 `SIG_MIN` 보다 작으면 폰 밝기 최대, 더 가까이, 앞 LED 반사 줄이기, 색 기준 조절 |
| 폰 빨간불을 정지 표지판으로 봄 (또는 반대) | 웹의 채움·흰색 % 를 보고 `SIGN_FILL_MAX`·`SIGN_WHITE_MIN` 조절. 폰 아래 버튼 칸이 화면을 많이 가리면 채움이 줄어듦 |
| 신호등이 없는데 신호가 잡힘 | 주변 물건·바닥 색. 픽셀 수를 보고 `SIG_Y1` 을 줄이거나 카메라 방향을 바꿈, `SIG_MIN` 을 올림 |
| 빨간불에 서서 안 움직임 | 신호등 인식을 끄거나(ESP 가 `n` 을 보내 풀어 줌), 초록으로 바꾸거나, 정지·수동 → 라인센서 주행 |
| ESP 가 꺼졌는데 차는? | 5초 안에 차가 스스로 수동·정지 (연결 신호 `h` 가 끊겨서). ESP 를 다시 켜고 블루투스 연결, 또는 안드로이드 굴노 앱으로 HC-06 에 붙기 |
| 업로드 "Failed to connect" | MB 보드 IO0 누른 채 RST → 떼고 다시. 다른 USB 케이블(데이터용) |
| 시리얼에 `E,camera` | 카메라 리본 케이블을 뺐다가 끝까지 꽂고 잠금. 업로드 직후면 USB 를 뺐다 꽂기 |
| 다 초기화하고 싶음 | `~/.pio-venv/bin/pio run -t erase` 후 다시 업로드 → 저장된 핫스팟·블루투스·설정이 지워짐 (설정용 암호도 새로) |

## 10. SD 카드 기록 (주행을 다시 보며 값 맞추기)

ESP32-CAM 뒤 슬롯에 **FAT32** 로 포맷한 마이크로 SD 를 꽂고 켜면 (맥 : 디스크 유틸리티 → 보기 "모든 기기 보기" → 카드 → 지우기 → MS-DOS(FAT), 마스터 부트 레코드. exFAT 은 안 됨) 웹 화면 **SD 기록** 버튼이 켜진다.

| 파일 | 내용 |
|---|---|
| `rec_NNNN.mjpeg` | 컬러 영상 (신호등 인식이 켜져 있으면 테두리 = 그때 신호 색), 0.2초마다 한 장 (초당 5장), 160x120, JPEG 품질 85 (웹 영상 40 보다 선명) |
| `log_NNNN.csv` | 0.1초마다 한 줄 : `ms,frame,fps,heap,sig_mode,sig,red,green,yellow,fill,white,stop_ms,bt,car` (sig 4 = 정지 표지판, fill·white = 빨강 덩어리 채움·흰색 %, stop_ms = 표지판 정지 남은 시간) |

- `frame` = 그때까지 저장한 영상 장 수 → 로그 줄과 영상 장면을 맞춰 봄. `red,green,yellow` = 그때 센 색 픽셀 수. `car` = 아두이노 상태 줄 그대로 ("ar,23,011,LINE,1,60").
- 누를 때마다 번호가 1씩 올라감 (기록마다, 껐다 켜도 이어짐).
- 보기 : SD 를 맥에 꽂고 **`esp32/rec_viewer.html`** 을 크롬·사파리로 열어 `rec_NNNN.mjpeg` 와 `log_NNNN.csv` 를 같이 고름 (끌어다 놓아도 됨). 영상을 한 장씩 넘기며 그 장면의 로그(신호, 색 픽셀 수, 차 상태 줄)를 옆에 보여 주고, 아래 그래프(빨강·초록·노랑 픽셀 수, 판단한 신호)를 누르면 그 장면으로 감. 예전 기록(라인 위치 열)도 열림. 설치·인터넷 필요 없음. QuickTime 은 .mjpeg 를 못 엶 (VLC 는 됨, `ffmpeg -i rec_0001.mjpeg rec_0001.mp4` 로 바꿔도 됨).
- 2초마다 SD 에 실제로 씀 → 전원이 갑자기 꺼져도 그 전까지는 남음. 끝낼 때는 **SD 기록 : 끔** 을 누른 뒤 카드 빼기.
- 기록 작업은 코어 0 에서, **기록할 때만** 카드를 붙이고 작업을 띄움 (2026-11-16 실측 : 내부 메모리 평소 78KB → 기록 중 70KB → 끄면 78KB 로 돌아옴, 처리 속도는 그대로).
- 기록을 켜는 순간 카드를 붙이느라 웹 화면이 잠깐(1~3초) 멈출 수 있음.
- 1비트 모드 (GPIO 2·14·15). 4비트 모드는 앞 LED(GPIO4)와 겹쳐서 쓰지 않음.
- 고화질(320x240) 기록은 이 카메라 드라이버가 달리는 중에 크기를 못 바꿔서 (`cam_hal: FB-SIZE` 오류) 하지 않음.
