# 2026-11-11 작업 보고 (추가 프로젝트 : ESP32-CAM 카메라)

제출용 차량 코드(버전 C, `main`)와 따로, ESP32-CAM 으로 바닥 라인을 보고 와이파이 화면으로 보여 주며 블루투스로 차를 조종하는 추가 프로젝트.
이 브랜치(`extra/esp32cam`)에서만 이어 간다. 자세한 사용법은 [`docs/CAMERA.md`](CAMERA.md).

## 지금 구조

```
 5V 외부 전원 ──▶ ESP32-CAM (OV2640 컬러 160x120, ESP32-D0WD-V3, 내부 메모리 약 320KB + 외부 PSRAM 4MB, 플래시 4MB)
                   ├ 화면 아래부터 이어지는 검은 라인을 한 줄씩 따라가며 찾음 → 직진 / 좌회전 / 우회전 판단
                   ├ 와이파이 (내 핫스팟, 프린터처럼 설정) ──▶ 폰·노트북 http://gulno-cam.local
                   └ 블루투스 ──▶ HC-06 ──▶ 아두이노 (버전 C 그대로)
```

## 잘된 점

- **ESP32 에 코드 올리기와 시리얼 확인** : ESP32-CAM-MB 받침 보드로 맥에서 바로 업로드, 시리얼 `I,` 안내 줄로 상태 확인.
- **와이파이를 프린터처럼** : 처음엔 설정용 와이파이(`GULNO-CAM-SETUP-xxxx`, 무작위 암호)를 켜고, 폰으로 핫스팟 이름·암호를 넣으면 ESP32 안에 저장해서 다음부터 바로 접속. 공개돼 있던 고정 암호를 없앰. 못 붙으면 이유를 보여 주고 10초마다 다시 찾음.
- **맥에서 접속** : 아이폰 핫스팟이 맥에는 IPv6 만 줘서 안 열리던 문제 → ESP32 에 IPv6 를 켜서 `gulno-cam.local` 로 열림.
- **블루투스 + 와이파이 + 카메라 동시 동작** : Arduino IDE 용 라이브러리로는 내부 메모리가 모자라 블루투스를 켜면 멈췄다. PlatformIO 로 ESP32 라이브러리를 다시 빌드해서 블루투스·와이파이 메모리를 외부 메모리(PSRAM)에 두고 BLE 를 꺼서 해결 (블루투스 켠 뒤에도 내부 메모리 20~40KB 남음).
- **블루투스 기기 찾기·연결** : 화면에서 기기를 찾아 목록(이름·주소·신호)에서 고르면 연결, 고른 기기는 저장. HC-06 연결 확인.
- **라인 인식을 눈으로 확인** : 인식한 라인은 초록으로 칠하고, 라인 가운데 경로(노란 점), 차가 향할 곳(빨간 선·점)을 영상 위에 그림. 좌우 반전 기본, 위아래 뒤집기 스위치.
- **반응형 웹 화면** : 노트북은 두 칸(영상 / 조종·상태), 폰은 한 줄로. 키보드 조종(방향키, Q·E, 스페이스).
- **주고받기를 웹소켓 하나로** : 조종 글자는 바로 보내고, 카메라 판단·차 상태(아두이노 상태 줄)는 0.2초마다 밀어 줌. 연결 신호 `h` 는 화면이 열려 있는 동안 ESP32 가 대신 보냄 (화면을 닫으면 자동 주행이 멈추는 안전장치 유지).
- **앞 LED 상태 표시** : 연결 중 깜빡, 다 연결되면 켜짐 (바닥 비춤). 뒤 빨간 LED 는 와이파이 상태.
- **잡음 신호 없어짐**, 연결이 전반적으로 안정됨.

## 안된 점 / 한계

- **Arduino IDE 로는 이 카메라 코드를 올리면 안 됨** : 예전 라이브러리로 빌드돼서 블루투스를 켜면 멈춘다. 반드시 PlatformIO.
- **처음 빌드가 무거움** : ESP32 라이브러리를 다시 만드느라 약 2GB 다운로드, 20~40분. pioarduino 버전 판단 문제로 처음 빌드가 한 번 멈추면 다시 실행해야 함.
- **블루투스 연결 중 조종이 조금 느림** : 안테나 하나를 와이파이·블루투스가 나눠 써서. 연결 중에는 영상을 초당 5장·압축 25 로 줄여 완화. 블루투스와 같이 쓰면 와이파이 절전을 끌 수 없어 핫스팟 지연도 조금 있음.
- **HC-06 은 한 번에 한 기기만** : ESP32 가 붙어 있으면 폰 굴노 앱은 블루투스로 못 붙음.
- **카메라는 아직 보여 주기만** : 차는 여전히 아두이노 라인센서 3개로 달린다.
- 시행착오 : 영상을 다른 포트(81)로 보냈더니 브라우저가 막음 → 서버 하나로 합침. 웹소켓 첫 연결 때 등록이 안 되던 문제 → 화면이 첫 글자 `h` 를 보내 등록.

## 앞으로 할 것

1. 카메라를 차 앞에 달고(바닥을 약 45°), 실제 트랙에서 라인이 초록으로 잘 잡히는지 확인. 안 잡히면 `DARK_OFFSET` 조절.
2. 웹 화면으로 HC-06 연결 후 실제 주행 조종 시험.
3. **카메라로 직접 주행 (다음 실험)** : 라인센서 자동과 카메라 자동을 둘 다 둔다. 라인센서 3개(간격 4.9cm)의 한계를 카메라로 넘기.
   - 아두이노(버전 C) : 모드 `a` = 라인센서 자동(그대로), `c` = 카메라 자동(새로). 카메라 자동은 PID 오차만 ESP32 가 보낸 값으로 쓰고 나머지(코너·선 찾기·장애물·안전장치)는 그대로. 카메라 값이 0.2초 넘게 안 오면 라인센서로 / 정지. 버전 D(`team2_bt_cam`)의 카메라 PID 를 블루투스용으로 옮김.
   - ESP32 : 카메라 자동일 때 라인 위치를 `#E-35` 같은 줄로 블루투스로 초당 약 20번.
   - 웹 화면 : "라인센서 자동" / "카메라 자동" 버튼. PROTOCOL.md 에 `c`, `#E` 추가 (폰 앱은 그대로).
   - 교안 2팀 심화 B(47쪽) : 영상 지연 몇 ms 인지 재기.
4. 블루투스 연결 중 조종이 더 느리면 영상을 더 줄이거나 조종할 때 영상 끄기 버튼.
5. **테슬라식 화면 (영상 대신 그리기)** : 지금(테스트 단계)은 실제 영상으로 라인 인식을 눈으로 확인한다. 인식이 믿을 만해지면 영상은 끄고, ESP32 는 인식 결과(줄마다 라인 왼쪽·오른쪽 끝, 향할 곳, 판단)만 웹소켓으로 보내고 브라우저가 차 아이콘·라인 모양·경로를 그린다. 한 번에 100~200바이트라 영상(장당 3~4KB, 초당 5~10장)보다 훨씬 가볍고, 남는 안테나 시간이 블루투스 조종으로 가서 빨라진다. 카메라 각도·조명 확인용으로 "사진 한 장" 버튼만 남긴다.
