# PID 기초와 우리 차(버전 C)의 PID

버전 C (`arduino/team2_bt_pid/team2_bt_pid.ino`) 가 선을 따라가는 방법을 처음부터 설명한다.

---

## 1. PID 가 뭔가

**목표에서 얼마나 벗어났는지(오차)를 계속 재서, 그만큼 되돌리는 방법.**

자전거를 타면서 선 위를 따라간다고 생각하면 된다.

- 선에서 **많이** 벗어났다 → 핸들을 **많이** 꺾는다 (P)
- 계속 한쪽으로 **밀린다** → 시간이 갈수록 **더** 꺾는다 (I)
- 선 쪽으로 **빠르게 돌아오는 중** → 지나치지 않게 **미리 덜** 꺾는다 (D)

```
          ┌──────────┐  오차   ┌─────────┐ 보정  ┌──────────┐
  목표 ──▶│ 목표-현재 │──────▶│   PID   │─────▶│  모터    │──┐
 (선 가운데)└──────────┘        └─────────┘       └──────────┘  │
               ▲                                                 │
               └───────────── 라인센서로 다시 잼 ◀───────────────┘
                              (20ms 마다 반복)
```

```
보정 = Kp × 오차  +  Ki × (오차를 시간 동안 더한 것)  +  Kd × (오차가 변한 정도)
       ──── P ────     ──────────── I ────────────       ──────── D ────────
```

### P (비례, Proportional) : 지금 벗어난 만큼

- 오차가 2 면 1 일 때보다 2배 꺾는다.
- **Kp 가 작으면** 커브에서 덜 꺾어 바깥으로 빠진다.
- **Kp 가 크면** 조금만 벗어나도 확 꺾어서 선을 지나쳐 반대로 넘어가고, 다시 확 꺾고… **좌우로 흔들린다.**

### I (적분, Integral) : 오래 벗어나 있던 만큼

- 오차를 시간 동안 계속 더한 값. 같은 쪽으로 오래 밀려 있으면 점점 커진다.
- 길게 도는 커브나, 한쪽 모터가 약해서 계속 한쪽으로 쏠리는 것을 잡는다.
- **Ki 가 크면** 커브가 끝나도 쌓인 값 때문에 계속 꺾어서 반대쪽으로 휘청인다. 아주 조금(0.1~0.3)만 쓴다.

### D (미분, Derivative) : 오차가 변하는 순간

- 오차가 커지는 중이면 더 꺾고, 줄어드는 중(선으로 돌아오는 중)이면 덜 꺾는다. **브레이크 역할.**
- P 때문에 생기는 흔들림을 줄인다.
- **Kd 가 크면** 오차가 바뀔 때마다 툭툭 튀고 커브 진입이 굼떠진다.

## 2. 우리 차에 맞게 바꾼 것

### 2-1. 오차 : 라인센서 3개 (0/1) 로 만든다

센서가 아날로그 값 없이 **검은 선 = 1, 흰 바닥 = 0** 만 나오므로, 세 센서 조합을 오차로 바꾼다.

| 왼 가운데 오른 | 오차 | 뜻 | 차가 하는 일 |
|---|---|---|---|
| 0 1 0 | 0 | 선이 가운데 | PID (직진) |
| 0 1 1 | +1 | 선이 살짝 오른쪽 | PID (오른쪽으로 살짝) |
| 1 1 0 | −1 | 선이 살짝 왼쪽 | PID (왼쪽으로 살짝) |
| 0 0 1 | +2 | 오른쪽 끝 센서만 = **오른쪽 코너** | **코너 회전** (오른쪽, 바깥 180 / 안쪽 −90) |
| 1 0 0 | −2 | 왼쪽 끝 센서만 = **왼쪽 코너** | **코너 회전** (왼쪽) |
| 0 0 0 | ±3 | 선 놓침 | 먼저 PID 로 마지막 쪽 0.5초 보정, 없으면 마지막 쪽으로 크게 0.5초, 반대쪽 1초 찾고 정지 |
| 1 1 1 | 0 | 교차선 | 직진, 0.5초 넘게 계속이면 선 끝으로 보고 정지 |

### 2-2. 직선과 완만한 커브 : PID (오차 0, ±1)

```
왼쪽 바퀴  = 기본 속도 + 보정
오른쪽 바퀴 = 기본 속도 − 보정          (보정이 + 면 왼쪽이 빨라져 오른쪽으로 돎)
```

- 20ms 마다 한 번 계산한다 (`PID_MS`).
- 안쪽 바퀴는 **0 까지만** 줄이고 뒤로 돌리지 않는다. 뒤로 돌리면 확 꺾여서 좌우로 흔들린다.

### 2-3. 코너 : 바깥·안쪽 바퀴 힘 따로 (오차 ±2, ±3)

이 차는 **핸들(조향)이 없다.** 좌우 바퀴 속도 차이로만 돈다.
안쪽 바퀴를 세워 두고 바깥만 돌리면, 4륜이라 안쪽 바퀴가 바닥에 걸려(락) 잘 안 돈다.
그래서 끝 센서만 선을 보면 바깥 바퀴는 `CORNER_OUT`(180) 으로 앞으로, 안쪽 바퀴는 `CORNER_IN` 으로 돌린다.
`CORNER_IN` 이 −170 이면 제자리 회전(확실하지만 요철에서 미끄러짐), 기본 −90 은 안쪽을 천천히 뒤로 돌려 4바퀴가 모두 돌며 돈다. (−220 제자리 회전은 실제 트랙에서 선 놓칠 때 한 바퀴씩 돌아 버려 되돌림)
모터 감속기가 작아 힘이 약하므로, 코너에서도 수동 조종처럼 0 이 아니면 최소 90, 방향이 바뀌는 순간 0.12초 최대 힘(255)을 준다. 작은 값(−60 등)은 바퀴가 안 돌고 끌려서 락이 걸린다.
가운데 센서가 선을 다시 보면 PID 로 돌아간다. 이때 쌓인 I, D 는 0 으로 비워서 튀지 않게 한다.

```
   직선 (PID)            코너
   ▲      ▲               ▲        ▼
  [왼]   [오]            [왼]     [오]       ← 오른쪽 코너 : 왼쪽 앞으로, 오른쪽은 천천히 뒤로
  120    120             180      -90
```

### 2-4. D 를 0.1초 동안 이어지게

센서가 0/1 이라 오차가 0 → 1 처럼 **계단으로** 바뀐다. 보통 D 는 바뀐 그 한 번(20ms)만 생겼다 사라져서,
모터가 반응하기도 전에 끝난다. 그래서 바뀐 순간 생긴 D 를 20ms 마다 0.8 배씩 줄이며 약 0.1초 이어지게 했다.

```
D항 = D항 × 0.8 + Kd × (오차 − 직전 오차)       (D_DECAY = 0.8)
```

### 2-5. I 가 너무 쌓이지 않게

- 오차가 반대쪽으로 넘어가면 0 으로 비운다.
- ±50 을 넘지 않는다 (`I_LIMIT`).

## 3. 코드에서 고칠 곳

`arduino/team2_bt_pid/team2_bt_pid.ino` 맨 위 `[설정]`

| 이름 | 지금 | 뜻 |
|---|---|---|
| `KP` | 51 | 오차 1 당 보정 |
| `KI` | 0.2 | 누적 오차 1 당 보정 |
| `KD` | 30 | 오차가 한 칸 바뀔 때 보정 |
| `BASE` | 120 | 직선 기본 속도 |
| `CORNER_OUT` | 180 | 코너·선 놓침 때 바깥 바퀴 (새 배터리에서 220 은 너무 크게 돎. 배터리 약해지면 200~220) |
| `CORNER_IN` | −90 | 코너·선 놓침 때 안쪽 바퀴 (−170 제자리 회전. 절댓값이 90 보다 작으면 90 으로 올림) |
| `D_DECAY` | 0.8 | D 가 줄어드는 비율 (작을수록 빨리 사라짐) |
| `LOST_PID_MS` | 500 | 선 놓침 : 먼저 PID 로 마지막 쪽으로 보정하는 시간 (앞으로 가며 완만히) |
| `LOST_STOP_MS` | 500 | 선 놓침 : 마지막으로 본 쪽으로 찾는 시간 |
| `BACK_SEARCH_MS` | 1000 | 그래도 없으면 반대쪽으로 찾는 시간, 지나면 정지 |

계산하는 곳은 `pidLine()` 함수. 고친 뒤 다시 업로드한다.

## 4. 맞추는 순서

차를 트랙에 올리고 **한 번에 하나만** 바꾼다. 시리얼 모니터(115200)의 `라인=` `오차=` `보정=` `모터L= R=` 를 보면서 한다.

1. **Ki = 0, Kd = 0** 에서 시작한다.
2. **Kp** 를 올린다 (+5~10 씩). 직선에서 선을 따라가면서 살짝 흔들리기 시작하는 값 바로 아래가 좋다.
3. 좌우로 흔들리면 **Kd** 를 올린다 (+10 씩).
4. 코너에서 덜 돌거나 안쪽 바퀴가 안 돌면 **CORNER_IN** 을 더 음수로 (−90 → −110), 단 −130 보다 세게 하면 오히려 바퀴가 비벼서 덜 돈다 (시뮬레이션). 그래도 덜 돌면 **CORNER_OUT** ↑.
5. 긴 커브에서 점점 밀리거나, 직선에서 계속 한쪽으로 쏠리면 **Ki** 를 조금 (0.1 씩).
6. 다 되면 **BASE** 를 올려 보고 2번부터 다시.

| 증상 | 고칠 것 |
|---|---|
| 직선에서 좌우로 흔들림 | Kp ↓ 또는 Kd ↑ |
| 직선에서 선을 따라가는 게 굼뜸 | Kp ↑ |
| 코너에서 덜 돌아 바깥으로 빠짐 | CORNER_IN 더 음수, CORNER_OUT ↑, BASE ↓ |
| 코너에서 너무 돌아 반대로 넘어감 | CORNER_IN −90 쪽으로 |
| 요철에서 코너 중 바퀴가 헛돎 | CORNER_IN −90 쪽으로 (제자리 회전은 접지력이 많이 필요) |
| 코너에서 안쪽 바퀴가 안 돌고 끌림(락) | CORNER_IN 더 음수 (−130), 배터리 확인 |
| 코너 끝나고 반대로 휘청 | Ki ↓ (0 으로) |
| 계속 한쪽으로 쏠림 | Ki 조금 ↑, 또는 수동 `TRIM_L` / `TRIM_R` |
| 오차가 바뀔 때마다 툭툭 튐 | Kd ↓ |

## 5. 한계와 더 좋게 하려면

- 센서가 3개, 0/1 뿐이라 오차가 −1, 0, +1 세 칸뿐이다. 가운데 센서 폭 안에서 얼마나 치우쳤는지는 모른다.
  그래서 아주 매끄럽게 가운데를 따라가지는 못하고 살짝 왔다 갔다 한다.
- **센서 간격 ≈ 선 폭** 이어야 `0 1 1` 같은 중간 단계가 자주 나온다. 간격이 넓으면 테이프를 넓힌다.
- 센서 감도(가변저항)를 흰색 0, 검정 1 이 확실히 나오게 맞춘다. 경계에서 깜빡이면 오차가 튄다.
- 더 매끄럽게 하려면 센서를 5개로 늘리거나 아날로그 출력 센서를 쓴다.
