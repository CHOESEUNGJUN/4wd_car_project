# 카메라(ESP32-CAM) 라인 인식 + 카메라 주행 — ESP32 펌웨어 + 아두이노 버전 D

> 이 브랜치(`extra/esp32cam`)의 추가 프로젝트. 2026-11-11 작업 보고 : [`REPORT_20261111.md`](REPORT_20261111.md)

라인센서 3개 대신 ESP32-CAM 카메라로 선을 본다. 센서 3개는 오차가 −3 ~ +3 일곱 칸뿐이지만,
카메라는 선 위치를 **−100 ~ +100 연속값**으로 주고, 화면 위쪽(먼 곳)으로 **커브를 미리** 본다.

| 파일 | 어디에 올림 |
|---|---|
| `esp32/esp32cam_line/esp32cam_line.ino` | ESP32-CAM (보드: AI Thinker ESP32-CAM) |
| `arduino/team2_bt_cam/team2_bt_cam.ino` | 아두이노 UNO (**버전 D** = 버전 C + 카메라 주행 글자 `G L R Q W`) : Arduino IDE |

---

## 1. 구조

```
 5V 외부 전원 ──▶ ESP32-CAM (OV2640 컬러, 160x120)
                   ├ 바닥을 찍어 화면 아래부터 이어지는 검은 라인을 따라가며 찾음 → 직진 / 좌회전 / 우회전 판단
                   ├ 와이파이 (내 핫스팟) ──▶ 폰·노트북 브라우저 http://gulno-cam.local
                   │      영상, 선 판단, 차 상태, 조종 버튼, 블루투스 기기 목록, LED·어두움 설정
                   └ 블루투스 ──▶ HC-06 ──▶ 아두이노 (버전 C 그대로)
                          조종 글자(g b l r q w s a m h)를 보냄, 아두이노 상태 줄("ar,23,011,LINE,1,60")을 받아 화면에 표시
```

- ESP32-CAM 은 **5V 외부 전원**으로 따로 켜고, 아두이노와는 **블루투스로만** 주고받는다 (선 없음).
- 웹 서버 하나(포트 80)가 화면·조종·영상을 다 한다. 영상은 노트북·폰 2개 화면까지 동시에.
- 메모리 : 와이파이·블루투스는 ESP32 내부 메모리(약 320KB)만 쓸 수 있어 빠듯하다. 그래서 사진 버퍼는 전부 외부 메모리(PSRAM 4MB)에 두고, 블루투스는 화면에서 "기기 찾기"나 "연결"을 누를 때만 켠다. 시리얼 `I,heap,<남은>,<가장 큰 덩어리>` 로 확인.
- SD카드는 필요 없다 (사진은 판단하고 바로 버림).

## 3. 배선

| ESP32-CAM | 연결 |
|---|---|
| 5V | **따로 5V** (보조배터리 USB, 또는 5V 강압 모듈). 와이파이·블루투스·카메라·LED 가 순간 0.5A 넘게 먹어서 아두이노 5V 로는 부족 |
| GND | 5V 전원 GND |

아두이노와 선은 잇지 않는다 (블루투스로 통신). 업로드할 때는 ESP32-CAM-MB 받침 보드에 꽂는다.

## 4. ESP32-CAM 에 업로드 (PlatformIO)

**Arduino IDE 로 올리면 안 된다** (예전 라이브러리로 빌드돼서 블루투스를 켜면 멈춤). 차(UNO) 코드는 지금처럼 Arduino IDE.

1. 처음 한 번 : `python3 -m venv ~/.pio-venv && ~/.pio-venv/bin/pip install platformio`
2. ESP32-CAM 을 **ESP32-CAM-MB** 받침 보드에 꽂고 USB 연결.
3. 올리기 : `cd esp32/esp32cam_line && ~/.pio-venv/bin/pio run -t upload` (포트를 못 찾으면 `--upload-port /dev/cu.usbserial-xxxx`)
4. 시리얼 : `~/.pio-venv/bin/pio device monitor` (나가기 Ctrl+C)

- 처음 빌드는 ESP32 라이브러리를 `platformio.ini` 의 설정으로 다시 만드느라 약 2GB 를 받고 20~40분 걸린다. 그다음부터는 1분 안팎.
- 처음 빌드가 `IncompatiblePlatform ... PlatformIO Core v6.2.0-post.1` 로 멈추면 같은 명령을 한 번 더 실행하면 이어서 된다 (pioarduino 버전 판단 문제).
- 업로드가 "Failed to connect" 면 MB 보드 IO0 버튼을 누른 채 RST → 떼고 다시.
- `huge_app.csv` (큰 앱 파티션), `page.h` (웹 화면) 도 같은 폴더에 있어야 한다.

## 5. 와이파이 연결 (프린터처럼)

핫스팟 이름·암호는 **코드에 적지 않는다** (공개 저장소). 처음 한 번 폰으로 넣어 주면 ESP32 안에 저장된다.

1. 연결할 와이파이를 켠다 — 폰 핫스팟이면 **2.4GHz** 여야 한다 (아이폰 : 설정 → 개인용 핫스팟 → **호환성 최대화** 켜기).
2. ESP32-CAM 을 켠다. 저장된 핫스팟이 없거나 15초 안에 못 찾으면 **설정 모드** : 설정용 와이파이 `GULNO-CAM-SETUP-xxxx` 가 켜진다.
3. 설정용 와이파이 암호는 처음 켤 때 무작위 8글자로 만들어 저장한다. **ESP32-CAM-MB 를 USB 로 꽂고 시리얼 모니터(9600)** 를 열면
   `I,setup,GULNO-CAM-SETUP-xxxx,<암호>` 가 10초마다 나온다. 이 암호를 종이에 적어 두면 프린터 스티커처럼 계속 쓸 수 있다.
4. 폰에서 그 와이파이에 접속 → 설정 화면이 자동으로 뜬다 (안 뜨면 브라우저로 http://192.168.4.1).
5. 핫스팟 이름(목록에서 고름)과 암호를 넣고 **저장하고 연결** → 카메라가 다시 켜지며 그 핫스팟에 붙고, 설정용 와이파이는 꺼진다.
6. 폰도 그 핫스팟으로 돌아가서 **http://gulno-cam.local** (안 되면 시리얼의 `I,ip,<주소>`).

- 다음부터는 켜면 바로 핫스팟에 붙는다. 핫스팟을 바꾸려면 그 핫스팟을 끈 채로 카메라를 켜면 설정 모드가 된다.
- 켤 때 못 붙으면 설정 모드가 되지만, 저장된 핫스팟을 10초마다 다시 찾아서 보이면 알아서 붙는다. 못 붙은 이유는 시리얼 `I,fail,<핫스팟>,<이유>` 와 설정 화면에 나온다.
- 아이폰 핫스팟은 맥·아이폰에 IPv6 만 주기도 한다 (맥 주소가 `192.0.0.2`). 그래서 ESP32 도 IPv6 를 켜 두었다 → 맥 크롬에서 **http://gulno-cam.local** 로 열면 된다 (숫자 주소 172.20.10.x 로는 안 열릴 수 있음).

### 웹 화면 (http://gulno-cam.local)

노트북은 두 칸(왼쪽 영상, 오른쪽 조종·상태), 폰은 한 줄로 아래로 이어진다.

| 칸 | 내용 |
|---|---|
| 위 배지 | 카메라 연결 / 차 블루투스 연결 / 초당 장수 |
| 영상 | 컬러 영상 위에 **초록 = 인식한 라인**, 노란 점 = 라인 가운데 경로, 빨간 선·점 = 차가 향할 곳, 흰 점선 = 차 가운데. 왼쪽 위에 판단 (⬆ 직진, ⬅ 좌회전, ➡ 우회전, ✕ 선 없음, ╋ 교차선) |
| 조종 | ▲ ▼ ◀ ▶ ↺ ↻ ■, 자동으로 / 수동으로. 노트북은 방향키, Q·E 제자리, 스페이스 정지 (앱과 같은 규칙 : 누르는 동안 0.2초마다, 떼면 s 두 번, 0.6초마다 h) |
| 차 상태 | 아두이노 상태 줄을 풀어서 : 모드, 동작, 앞 거리, 라인센서 ○●○, 단계, 오차 / 보정 |
| 블루투스 | **기기 찾기** (약 5초) → 목록(이름 · 주소 · 신호)에서 차를 누르면 연결 (PIN 1234). 고른 기기는 저장돼서 다음엔 **연결** 만. **끊기** 하면 폰 앱이 HC-06 을 쓸 수 있다 |
| 카메라 설정 | 좌우 반전 (이 보드는 기본 켬) / 위아래 뒤집기 / **모폴로지 (빠름)** (바꾸면 저장). 컬러 = 테스트용 (실제 사진 위에 인식 결과), 모폴로지 = 라인 확인 후 (흰 바탕에 정리된 검정 라인만 : 카메라가 처음부터 흑백으로 찍어 변환이 없고, **JPEG 영상 대신 마스크를 줄마다 검정 구간(RLE)으로 웹소켓에 초당 10번, 한 번에 약 500바이트** 보내서 브라우저가 그림. 컬러 JPEG 의 약 1/7). 모폴로지로 바꾸면 ESP32 가 저장하고 다시 켜짐 (몇 초) |

- **메모리** : Arduino IDE 용 ESP32 라이브러리로는 블루투스 클래식 + 와이파이 + 카메라를 같이 켤 내부 메모리가 없다 (블루투스를 켜면 멈춤). 그래서 **PlatformIO 로 ESP32 라이브러리를 다시 빌드**해서 블루투스·와이파이 메모리를 외부 메모리(PSRAM 4MB)에 먼저 두고, BLE 는 끈다 (`esp32/esp32cam_line/platformio.ini`). 이렇게 하면 블루투스를 켜도 내부 메모리가 20~40KB 남는다 (2026-11-11 시험 : HC-06 찾기·연결 정상, 영상 초당 2~3장으로 조금 느려짐).
- **라인 인식** : 줄마다 평균보다 `DARK_OFFSET`(40) 어두우면 라인 후보 (이진화) → **모폴로지 열림** (3x3 침식으로 작은 점·가는 잡음을 지우고, 3x3 팽창으로 라인 굵기를 되돌림) → 화면 아래부터 이어지는 검정 덩어리만 따라감. 바닥이 완전히 흰색이 아니어도 테이프보다 밝으면 됨.
- **메모리** : 사진·마스크 버퍼는 전부 외부 메모리(PSRAM). 0.2초마다 만드는 상태는 고정 크기 버퍼로 (메모리를 잡았다 놓았다 하지 않게). 실행 중에 카메라를 껐다 켜지 않음 (모드를 바꾸면 재시작).
- **카메라 주행** : 웹 화면 "카메라 주행" 버튼 (모폴로지 화면 + 차 블루투스 연결일 때만). ESP32 가 `m`(수동)을 보낸 뒤, 판단 위치(-100~100)를 ±20 안 = `G` 직진, ±50 안 = `L`/`R` 살짝, 그 밖 = `Q`/`W` 크게로 바꿔 0.15초마다 보냄. 아두이노 **버전 D(`team2_bt_cam`)** 는 수동 조종처럼 받되 속도는 자동 주행과 같음 (버전 C 는 이 글자를 무시) (`BASE` 120, PID ±1 정도, 코너 180/−90). 라인이 0.3초 넘게 안 보이거나, 화면을 닫거나, 사람이 조종 버튼을 누르면 멈춤. "라인센서 주행" 버튼은 그냥 `a` (아두이노 자동 모드).
- **주고받기는 웹소켓 하나** (`/ws`) : 화면을 열면 연결을 하나 열어 두고, 조종 글자는 바로 보내고(화면 → ESP32 → 블루투스 → 차), 카메라 판단·차 상태는 ESP32 가 0.2초마다 밀어 준다. 연결 신호 `h` 는 화면이 열려 있는 동안 ESP32 가 차에 대신 보낸다 (화면을 닫으면 끊겨서 자동 주행이 1.5초 뒤 멈춤).
- HC-06 은 한 번에 한 기기만 붙는다. ESP32 가 붙어 있으면 폰 굴노 앱은 블루투스로 못 붙는다.
- LED : 앞 흰색 플래시 LED 는 연결 중(설정 모드, 핫스팟 연결 중, 블루투스 연결 중) 깜빡, 다 연결되면 계속 켜짐 (바닥 비춤, 밝기 기본 30/255). 뒤 빨간 LED 는 와이파이 상태 (설정 모드 깜빡, 연결 켜짐).

## 6. 카메라 달기

- 차 앞쪽에, **비스듬히 아래**를 보게 (대략 45도). 화면 **아래쪽에 차 바로 앞 테이프**가, **위쪽 1/3 쯤에 10~20cm 앞 테이프**가 오게.
- 거꾸로 달았으면 웹 화면 카메라 설정의 좌우 반전 / 위아래 뒤집기로.

## 7. 맞추기

1. ESP32-CAM 전원을 켜고, 같은 핫스팟에 붙은 폰/PC 브라우저에서 **http://gulno-cam.local** (5장).
2. 컬러 화면에서 테이프가 초록으로 칠해지는지, 노란 점(경로)이 테이프 가운데를 따라가는지, 빨간 점(향할 곳)이 앞쪽 라인 위에 있는지 확인.
3. 바닥 무늬·이음새까지 잡거나 테이프를 못 잡으면 `esp32cam_line.ino` 의 `DARK_OFFSET`(40) 을 바꿔 다시 올림 (클수록 더 어두워야 라인).
4. 라인이 잘 잡히면 카메라 설정 "모폴로지"로 바꾸고 (재시작), 흰 바탕에 검정 라인만 깔끔하게 나오는지 확인.
5. 차에 **버전 D** (`team2_bt_cam`) 를 올리고 "카메라 주행". 너무 흔들리면 `CAM_SOFT`(20) 를 키우고, 커브에서 덜 꺾으면 `CAM_HARD`(50) 를 줄임.

ESP32 `[설정]` 의 값

| 이름 | 처음 값 | 뜻 |
|---|---|---|
| `DARK_OFFSET` | 40 | 그 줄 평균보다 이만큼 어두우면 라인 |
| `MAX_JUMP` | 18 | 한 줄 위로 갈 때 라인 가운데가 이보다 많이 튀면 다른 물체로 봄 (칸) |
| `LOOK_Y` | 42 | 향할 곳을 잡는 줄 (작을수록 멀리) |
| `CAM_SOFT` / `CAM_HARD` | 20 / 50 | 카메라 주행 : ±20 안 = `G`, ±50 안 = `L`/`R`, 그 밖 = `Q`/`W` |
| `CAM_LOST_MS` | 300 | 라인이 이만큼 안 보이면 정지 |
| `FLASH_DUTY` | 30 | 앞 LED 밝기 (0~255) |

버전 D 의 바퀴 힘은 버전 C 의 자동 주행 값(`BASE` 120, `KP` 51, `CORNER_OUT` 180 / `CORNER_IN` −90)을 그대로 쓴다. PID 기초는 [`PID.md`](PID.md).
