## 1. 카메라 (브랜치 `extra/esp32cam`)

시작 : `cd ~/4wd_car_project && git switch extra/esp32cam` → ESP32-CAM 을 MB 보드에 꽂고, 아이폰 핫스팟 켜기 (호환성 최대화).
올리기 : `cd esp32/esp32cam_line && ~/.pio-venv/bin/pio run -t upload` (약 40초. Arduino IDE 로 올리면 안 됨). 자세한 건 브랜치의 `docs/CAMERA.md`, `docs/REPORT_20261111.md`.

**원칙 (2026-11-16) : 카메라로 라인 주행은 하지 않는다.** 라인은 차가 라인센서 3개 + PID, 카메라는 신호등(표지판)만. 카메라 라인 인식·카메라 주행은 뺐음 (브랜치 커밋 `6fe7773` 까지 남아 있음).

- [x] 신호등 인식이 늦던 것 (약 2초) → 약 0.1\~0.15초 (2026-11-16, 카메라 버퍼 2장, 빨강 2장, 바뀌면 바로 보냄)
- [x] SD 기록 + 보기 페이지 `esp32/rec_viewer.html` (2026-11-16)
- [x] ESP32 에 신호등 전용 펌웨어 올리기 (2026-11-18 : HSV 색 판단, 블루투스 + 와이파이 메모리 문제 해결, HSV 영상)
- [x] 카메라를 차 앞에 달기 (2026-11-18) : **앞을 보게** (바닥 볼 필요 없음), 차 앞 30\~60cm 의 폰 신호등이 화면에 들어오게. 초음파 센서 안 가리기 (브랜치 `docs/CAMERA.md` 8장)
- [x] **신호등 기준 맞추기** (2026-11-18, 트랙 조명에서. 정지 표지판 흰색·초록 기준은 SD 로그로 한 번 더 다듬을 수 있음) : 웹 "신호등 인식 : 켬" → 신호등이 없을 때 빨강·초록·노랑 픽셀 수가 `SIG_MIN`(40)보다 한참 작은지 (주변 색이 걸리면 `SIG_Y1` 을 줄임), 아이폰 신호등 화면을 실제 거리에 두고 세 색이 넉넉히(수백 개) 잡히는지. 거리·밝기별 성공 횟수 기록 (교안 3팀 STEP 9). 서행 색은 노랑으로 먼저 : 날아가거나 헷갈리면 파랑(#0000ff) 이나 주황(#ff8000) 중에서 결정
- [x] **라인센서 주행 + 신호등** (2026-11-18 통과, SD 기록 log_0011·log_0012) : 차에 버전 D (`team2_bt_cam`, 저주파면 `motor_control_low_frequency_cam`) → 라인센서 주행 중 빨강 = 정지, 초록 = 다시 주행, 노랑 = 서행 (`SLOW_BASE` 100, 출발 못 하면 올림). SD 기록으로 찍어서 확인
- [x] **반응 시간 재기** (2026-11-18, SD 로그) : 빨간불 → 정지 0.21\~0.54초, 초록불 → 출발 0.11\~0.33초, 정지 표지판 → 정지 0.10\~0.22초
- [ ] **30분 버티기 (메모리·속도·전원·열)** — 4분 26초 주행은 재시작 없음, 내부 메모리 13\~25KB (2026-11-18) : 웹 화면 + 신호등 인식 + 블루투스 연결 (+ SD 기록) 을 켠 채 30분
  - 메모리 : 시리얼 `I,heap` 이 계속 줄면 누수, 오르내리며 일정하면 정상. `I,restart,low_heap` 이면 메모리 부족으로 스스로 재시작한 것
  - 속도 : 웹 fps, 시리얼 `I,time` (한 바퀴 약 50ms 면 정상)
  - 전원 : 주행 중 ESP 가 재시작하는지 (5V 외부 전원 따로, 모터 배터리와 나누기)
  - 열 : 끝나고 ESP32-CAM 을 만져 봄. 너무 뜨거우면 `FLASH_DUTY`(지금 20) 더 낮추기
- [x] **표지판** : 정지 표지판 (빨간 팔각형 + 흰 글자) → 3초 정지 후 출발, 빨간불과는 모양(채움·흰색)으로 가름 (2026-11-18)

- [x] **저주파 라인 주행 완성 (2026-11-16)** : 배선 바꿔 올려 보니 잘 돌고 더 부드러워짐 (트랙 주행 확인). 킥을 크게 줄임 (`KICK_PWM` 255 → 170, `KICK_MS` 0.12 → 0.06초). 빨간불·표지판 뒤 재출발 0.1\~0.3초 (2026-11-18). 원리와 코일 전류 비교는 [`PWM.md`](PWM.md) (MATLAB·Simulink)
- [x] **저주파 PWM 은 카메라 실험에서 먼저** (통과) : 브랜치의 `arduino/motor_control_low_frequency_cam` (버전 D + 저주파) 로 카메라 실험을 하면서 같이 시험 (배선 4개 맞바꿈은 아래와 같음). 거기서 잘 가면 버전 C 쪽 버전 E 도 되는 것. 안 좋으면 선 되돌리고 버전 D
- [x] **버전 E 저주파 PWM 시험 (2026-11-16 통과)** : 수동에서 툭툭 튀고 저속에 "삐-" 소리만 나는 문제. 배선 4개 맞바꿈 (L298N ENA 선 5 → 9, IN2 선 9 → 5, ENB 선 6 → 10, IN3 선 10 → 6) → `arduino/motor_control_low_frequency` 올림. 바퀴를 띄우고 먼저 전진·후진·회전 방향이 맞는지. 그다음 저속 힘·소리, `KICK_PWM` 255 → 180 으로 툭툭 줄이기, 트랙 한 바퀴 (PID·코너 값 다시 확인). 좋으면 버전 E 로 가고 버전 D 에도 같은 변경, 아니면 선을 되돌리고 버전 C (`docs/PID.md` 끝)
  - 결과 : 저주파로 바꾼 뒤 `KICK_PWM` 을 170 으로 줄임 (보고서 1장)
