- [ ] **라인센서 주행 + 신호등** : 차에 버전 D (`team2_bt_cam`, 저주파면 `motor_control_low_frequency_cam`) → 라인센서 주행 중 빨강 = 정지, 초록 = 다시 주행, 노랑 = 서행 (`SLOW_BASE` 100, 출발 못 하면 올림). SD 기록으로 찍어서 확인
- [ ] **반응 시간 재기** (교안 4팀 STEP 6) : 신호를 빨강으로 바꾼 순간 → 차가 서는 순간을 폰 슬로모션으로
- [ ] **30분 버티기 (메모리·속도·전원·열)** : 웹 화면 + 신호등 인식 + 블루투스 연결 (+ SD 기록) 을 켠 채 30분
  - 메모리 : 시리얼 `I,heap` 이 계속 줄면 누수, 오르내리며 일정하면 정상. `I,restart,low_heap` 이면 메모리 부족으로 스스로 재시작한 것
  - 속도 : 웹 fps, 시리얼 `I,time` (한 바퀴 약 50ms 면 정상)
  - 전원 : 주행 중 ESP 가 재시작하는지 (5V 외부 전원 따로, 모터 배터리와 나누기)
  - 열 : 끝나고 ESP32-CAM 을 만져 봄. 너무 뜨거우면 `FLASH_DUTY`(30) 낮추기
- [ ] (생각해 볼 것) **표지판** : 신호등 말고 어떤 표지판을 볼지 정하기 (예 : 정지 표지판 = 빨간 팔각형, 서행 구간 = 노란 판, "정지 후 N초 뒤 출발"). 색 덩어리 크기로 거리 어림 (교안 4팀 심화)

- [x] **저주파 PWM 첫 시험 (2026-11-16)** : 배선 바꿔 올려 보니 잘 돌고 더 부드러워짐. 아래 비교 기록·킥 줄이기는 아직
- [ ] **저주파 PWM 은 카메라 실험에서 먼저** : 브랜치의 `arduino/motor_control_low_frequency_cam` (버전 D + 저주파) 로 카메라 실험을 하면서 같이 시험 (배선 4개 맞바꿈은 아래와 같음). 거기서 잘 가면 버전 C 쪽 버전 E 도 되는 것. 안 좋으면 선 되돌리고 버전 D
- [ ] **버전 E 저주파 PWM 시험 (2026-11-13 컴파일만)** : 수동에서 툭툭 튀고 저속에 "삐-" 소리만 나는 문제. 배선 4개 맞바꿈 (L298N ENA 선 5 → 9, IN2 선 9 → 5, ENB 선 6 → 10, IN3 선 10 → 6) → `arduino/motor_control_low_frequency` 올림. 바퀴를 띄우고 먼저 전진·후진·회전 방향이 맞는지. 그다음 저속 힘·소리, `KICK_PWM` 255 → 180 으로 툭툭 줄이기, 트랙 한 바퀴 (PID·코너 값 다시 확인). 좋으면 버전 E 로 가고 버전 D 에도 같은 변경, 아니면 선을 되돌리고 버전 C (`docs/PID.md` 끝)
  - 비교해서 기록 (보고서용, 같은 배터리·같은 트랙) :

    | 비교 | 버전 C (980Hz) | 버전 E (122Hz) |
    |---|---|---|
    | 바퀴가 겨우 돌기 시작하는 PWM 값 (바퀴 띄우고, 바닥에서 각각. 60, 70, 80 … 올려 보기 = 교안 1팀 STEP 4) | | |
    | 소리 (삐- / 웅 / 떨림) | | |
    | 수동 출발이 튀는 정도 (`KICK_PWM` 255 / 180) | | |
    | 트랙 한 바퀴 시간, 선 놓친 횟수 (3번씩) | | |
    | 몇 바퀴 뒤 모터·L298N 온도 (손으로 : 미지근 / 따뜻 / 뜨거움) | | |

  - 저속 힘이 생기면 `MIN_PWM`·`KICK_PWM` 을 줄이고, 서행 `SLOW_BASE` 를 더 낮출 수 있는지도 (잘 되면 "우리 팀 제어 방식" 으로 보고서에)
